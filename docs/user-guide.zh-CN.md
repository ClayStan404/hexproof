# Hexproof 用户指南

[English version](user-guide.md)

- 适用读者：玩家和牌桌房主
- 适用范围：Hexproof 3.1.0 及 `hexproof.v2` 房间服务器；未发布改动会单独标明
- 更新日期：2026-10-25

Hexproof 提供手动万智牌牌桌和可选的 Forge 规则房间。手动牌桌同步卡牌、区域、指示物、生命和公开日志，卡牌文字、优先权、触发和目标由玩家自行处理；Forge 房间由所选规则引擎处理支持的对局操作。本地卡库的套牌检查与房间的规则模式是不同功能。

客户端和服务器的游戏协议必须相同（3.1.0 使用 `hexproof.v2`），应用版本号可以不同。3.0.0/v1 客户端需要更新后才能加入 v2 服务器。

## 1. 首次启动

1. 打开 **设置**，再进入对应分类。
2. 在**语言与卡牌**和**外观**中选择界面语言、卡牌语言与卡图偏好以及界面缩放比例。
3. 在**卡牌数据库**中下载或导入可搜索的卡牌数据库。
4. 打开 **套牌库**，至少导入一副套牌。
5. 创建房间、加入房间、浏览大厅或开始单人测试前，先连接房间服务器。

套牌库、套牌编辑器、设置、已安装的数据库以及下载的卡图都保存在当前电脑上。在线房间只同步游戏状态，不会在玩家之间传输卡图文件。

## 2. 窗口和通用导航

- **返回**会回到上一个界面。除非当前操作明确表示离开房间，否则不会断开连接。
- 从等待房间打开的页面（例如套牌库）会覆盖房间界面；返回后，原房间会话仍然保留。
- 删除套牌、解散房间和投降等破坏性操作会要求确认。
- 将鼠标悬停在可见卡牌上，会在鼠标附近显示无额外边框的大图预览。
- `F11` 用于切换原生全屏模式。
- 窗口宽度低于 1100 像素时，主菜单和等待房间会改为单列，牌桌左右栏会变窄。窗口最小尺寸为 900×620。宽屏主页标出手动、Forge 和限制赛；窄屏会隐藏这块介绍，先显示开局操作。

## 3. 主菜单

### 连接控制

- **连接服务器**打开服务器连接表单。
- 状态标记显示 **离线**或当前显示名称。
- **断开连接**关闭当前服务器会话。如果玩家正在房间中，也会同时离开该房间。

### 对局功能

- **创建房间**创建多人通用 1v1、法禁、指挥官或 Cube 自由对战房间。
- **单人测试**创建只有一个座位的私人测试牌桌。
- **使用房间码加入**通过已知的六位房间码加入房间。
- **浏览大厅**列出当前服务器上可以加入的多人房间。
- **赛事**列出比赛，并通过统一的**创建赛事**入口创建构筑、系列现开或系列轮抓比赛。

这些功能需要服务器连接；离线或已经处于房间中时会被禁用。

### 本地功能

- **套牌库**始终可用，包括离线状态。
- **设置**打开分类入口，分别管理外观、语言、卡牌数据、快捷键、更新和本机 Forge。每个分类都是独立页面。
- **模拟开包**位于主菜单“浏览大厅”旁边，进入本地开包模拟器，离线也可使用，不会创建线上赛事或修改套牌。
- **赞助与鸣谢**显示客户端内置的赞助人名单；存在个人主页按钮时，会使用系统浏览器打开。
- **反馈**打开反馈表单和**我的反馈**，离线也可保存草稿；参见[反馈与报告](#17-反馈与报告)。
- **退出 Hexproof**关闭应用程序。

每个版本首次启动时会自动弹出赞助鸣谢。关闭弹窗或打开完整名单后，本地会记住当前版本；同一版本后续启动不再弹出，升级到新版本后会再次显示一次。

## 4. 连接服务器

连接界面包含：

- **服务器**：选择**官方大厅（自动）**、目录中的官方节点或**自定义服务器**。节点名称和地址以当前服务器目录为准，不依赖固定的编号列表。官方大厅会在可用节点间安排房间和赛事；自定义地址使用 `ws://` 或 `wss://`，保存在本地。健康检查和延迟会标明不可用的节点。
- **显示名称**：访客游玩时其他成员看到的名称。官方账号登录是独立功能，参见[账号说明](accounts.md)。
- **连接**：建立 WebSocket 会话。**返回**离开本页，并取消尚未完成的连接。

连接错误会显示在页面提示条中。如果网络意外中断，Hexproof 会在尝试恢复原座位期间禁用牌桌操作。正常的断线重连保留时间为三分钟。

## 5. 单人测试

单人测试没有对手，但会使用真实的服务端权威牌桌流程。

1. 连接一个房间服务器。
2. 在主菜单选择 **单人测试**。
3. 选择套牌赛制。自定义、标准、先驱、摩登、薪传、特选和纯铁使用普通的
   20 点生命 1v1 牌桌：
   - 法禁以 20 点生命开始，并保留指挥官区和指挥官税。
   - 指挥官以 40 点生命开始，并保留指挥官区和指挥官税。
4. 选择卡图加载策略：
   - **进入游戏前预加载**：下载全部所需卡图后再打开牌桌。
   - **后台加载**：立即打开牌桌，优先下载当前可见卡牌，同时在后台下载其余卡图。
5. 选择 **创建单人测试**。
6. 选择一副赛制匹配且本地已就绪的套牌，然后选择 **准备**。

单人测试固定为 BO1，只有一个座位，不接受其他玩家或观战者，不会显示在大厅房间列表中，也不会保存为多人对局回放。唯一的战场会占满牌桌区域。使用 **结束测试**返回主菜单；此模式没有投降操作。

单人测试仍是手动牌桌：它不会执行卡牌文字，也不会检查操作是否合法。

## 6. 创建多人房间

创建界面提供：

- **房间名称**：初始为空，不显示示例名称；填写后会显示在等待房间和大厅房间列表中。
- **赛制**：
  - **自定义、标准、先驱、摩登、薪传、特选或纯铁**创建两个普通的
    20 点生命座位。自定义不限制牌池；命名赛制会在本地进行建议性套牌检测。
  - **法禁 · 2 人** 创建两个玩家座位，以 20 点生命开始，并包含指挥官区
    和手动指挥官税。Hexproof 不执行构筑规则、禁牌表或卡牌规则。
  - **指挥官 · 3–4 人** 提供四个玩家座位；三名或四名已入座玩家全部准备后即可开始。
  - **Cube** 使用已保存的 Cube 套牌创建 2–8 人轮抓房间。玩家入座准备后轮抓、
    组牌，再自行选择对手自由对战，不经过赛事报名流程。需要瑞士轮比赛时，
    请使用**赛事 → 创建赛事 → Cube 轮抓**。
- **比赛模式**：
  - **BO 1** 只进行一局。
  - **BO 3** 可用于无指挥官 1v1 和法禁。无指挥官 1v1 可在两局之间换备牌；
    法禁保持已登记套牌不变。
  - 指挥官固定为一局多人游戏。
- **允许观战者**：允许最多八名观战者查看公开状态。
- **观战者可见手牌**：开启后，所有观战者都可以持续查看每位玩家当前的
  手牌，但玩家之间仍不可互看。该设置创建房间后不能修改；房间浏览器和
  等待房间会明确显示警告。
- **卡图加载**：选择进入游戏前预加载或后台加载。
- **房间密码**：除房间码之外的可选访问限制。
- **创建房间**：以房主身份进入一号座位和等待房间。

普通牌桌的房主可以复制生成的房间码、移除其他玩家或观战者，以及解散房间。
Cube 房间由房主在全员准备后开始轮抓；房主离开时需要确认，并会关闭整间 Cube 房间。

普通桌面尺寸下，创建表单使用较紧凑的左右两列。表单较矮时，整张卡片垂直居中，
取消和创建按钮留在卡片里；Cube 或本机托管选项超出一页时，整张卡片可滚动。
窗口较窄或界面放大时，表单改为可滚动的单列。

## 7. 加入和浏览房间

### 使用房间码加入

- 输入六位 **房间码**。
- 选择 **玩家**或**观战者**。
- 房间受密码保护时输入密码。
- 选择 **加入牌桌**或**进入观战**。

赛制规定的全部座位都被占用后，无法再以玩家身份加入。观战需要房主允许，并且房间仍有空余观战名额。

### 浏览当前服务器

房间浏览器只显示当前服务器上的多人房间，包括：

- 房间名称、房间码、赛制和 BO1/BO3；
- 已占用的玩家座位数和观战者数量；
- 等待、加载或游戏中状态；
- 是否需要密码；
- 由服务器计算的 **加入**和**观战**可用状态。

Cube 自由对战房间也显示在这里，并区分等待、轮抓、组牌和自由对战阶段。
可以直接从列表或通过房间码加入，不需要赛事报名或签到。轮抓开始后不再
接受新玩家，原玩家返回时可以恢复原座位和牌池。

摘要数字是未筛选的大厅房间数。每一行对应其中一间房；除非搜索或筛选把结果全部藏掉，否则有计数时不会出现空列表。

可以用加入资格、等待/对局中、密码和牌桌类型筛选列表，按房间名或房间码搜索，
并按可加入优先、名称或空座位排序。使用 **刷新**重新请求列表。选择受密码保护的房间后，会转到加入表单。

## 8. 等待房间和对局加载

### 等待房间

- 座位列表显示占用情况、房主、套牌选择和准备状态。
- **选择套牌**只列出赛制匹配且本地已就绪的套牌。
- 所有必需座位都有人，并且本地玩家选择套牌后，才能 **准备**。
- **取消准备**恢复为可编辑状态。
- 更换已选择的套牌会自动取消准备。
- **套牌库**打开本地套牌库，但不会离开房间。
- **离开房间**放弃座位并返回主菜单。
- 房主可以 **移除**其他成员或 **解散房间**。
- 窗口宽度低于 1100 px 时，**套牌库**、**离开房间**和**解散房间**收入 **更多** 菜单，以便准备按钮保持可见。

等待房间没有单独的“开始”按钮。所有玩家都准备后，房间会自动按创建时选择的卡图加载策略开始。

### 预加载界面

- 进度条显示本场对局已经解析完成的卡牌数量。
- 每个座位会显示该客户端是否完成加载。
- **重试失败项**重新请求失败的卡牌数据或卡图。
- **取消准备**取消本地准备状态，并让房间返回等待阶段。
- **离开房间**退出当前房间。

选择后台加载的房间会跳过这个阻塞式加载界面。

## 9. 套牌库

### 套牌列表

- 可以按 **全部**或任一支持的套牌赛制筛选。
- 每一行显示赛制、主牌数量、备牌数量、指挥官和本地就绪状态。
- 双击一行或选择 **编辑**打开套牌编辑器。
- **导出**可将套牌表复制到剪贴板，或保存为带明确 `Deck`、`Sideboard`、`Commander` 和可选 `Consider` 分区标题的 `.txt` 文件，以便再次导入。
- **删除**只删除本地套牌列表；共享的已下载卡图仍然保留在缓存中。
- **导入套牌**打开文本/文件导入器。
- **缓存卡图**会下载本地所有套牌中缺失的卡图。
- **重试失败项**会重新请求套牌库中失败的卡牌数据或卡图。
- **设置**打开设置分类，包括卡牌数据库和语言。

套牌未通过基础操作检查、必需卡牌数据/卡图尚未解析，或当前命名赛制存在已验证的阻断性违规时，套牌无法就绪。检测包括主牌与备牌数量、同名牌数量、Scryfall 赛制合法性与限制牌，以及适用时的指挥官单例和色组。指挥官/EDH 主牌不是正好 100 张时只显示提醒，不会阻止选择套牌或进入房间；该赛制的禁牌、未发布牌、本地数据库无法识别的牌和颜色认同不匹配同样只作提醒。法禁仍会阻止不符合 100 张和牌池规则的套牌。数据库缺失或过旧时只显示“未验证”，不会误判为非法。

### 导入套牌

1. 输入套牌名称。
2. 选择自定义、标准、先驱、摩登、薪传、特选、纯铁、法禁或指挥官。
3. 粘贴 Moxfield 或常见纯文本格式导出的套牌，或者选择 **选择文件…**
   载入本地 UTF-8 `.txt`/`.dec` 牌表。载入后仍可编辑文本；套牌名称为空时，
   文件名会自动成为初始名称。
4. 选择 **导入套牌**。

按钮会立即切换为解析状态。较大的指挥官牌表会在后台解析。导入完成后会先在本地缓存中匹配已有卡图并立即回填，缺图数量只计算真正不存在的文件；这一步不会访问网络，导入仍然不会整副下载卡图。客户端启动、切换卡牌语言或替换数据库后，也会对已有套牌中仍缺路径的卡牌执行同样的本地回填。

常见的套牌行格式如下：

```text
Deck
4 Lightning Bolt (M11) 149
1 Sol Ring

Sideboard
2 Wear // Tear

Commander

Consider
1 Doubling Season
```

**导出**会按同一格式写入剪贴板或 UTF-8 `.txt` 文件（指挥官只出现在 `Commander` 分区，并带 `*CMDR*`），不包含本地衍生物偏好。将该文本再导入可恢复主牌、备牌、指定指挥官和可选的备选区。

成功识别的主牌和备牌条目会保存到本地。卡牌类型和编辑器分类来自已安装的本地数据库，不必等 **缓存卡图**。如需调整印刷版本，可先在编辑器中选好，再选择 **缓存卡图** 下载其余缺失卡图。从搜索添加卡牌或更换印刷版本时，只会立即下载那一张卡图。

### 套牌编辑器

- 修改会自动保存。点击顶栏套牌名即可改名。
- 使用赛制下拉框可以直接修改当前套牌，不必重新导入。普通 1v1 赛制之间会直接切换；切换到法禁或指挥官时会先确认，把全部备牌合并进主牌并清空指挥官选择；切回普通 1v1 时只清除指挥官身份，卡牌仍保留在主牌中。整个过程不会删除卡牌。
- 编辑器顶栏的 **更多 → 导出** 会按上述 `Deck` / `Sideboard` / `Commander` / 可选 `Consider` 文本格式复制或保存当前套牌。
- **更多 → 缓存卡图** 会下载当前套牌中其余缺失的卡图。搜卡、备选和衍生物仍留在主工具栏。
- 套牌内搜索只筛选当前套牌中已有的卡牌。
- 使用 **视图** 在紧凑列表和卡图编辑模式之间切换。每个分类标题会显示实际张数；卡图模式会保留一张较大的预览图，并可按卡牌类别、法术力值或不分组显示，再按名称、法术力值或卡牌类别排序。
- 数据库搜索会打开和衍生物选择类似的弹窗，只用来查找并添加卡牌，不会在搜索界面里编辑主牌列表。它支持中文或英文卡名，并可按牌类、系列代码、印刷语言、颜色认同、稀有度以及各赛制合法性筛选；不输入卡名也可以只使用筛选条件。先搜索并点选结果，再选择加入主牌、备牌或备选。指挥官和 Cube 不显示备牌。命名赛制的套牌还会使用本地数据库异步检测；把鼠标悬停在套牌状态上可查看全部问题。指挥官/EDH 的非 100 张主牌、禁牌、未发布牌、本地数据库无法识别的牌和颜色认同不匹配都只显示警告，不会阻止选择套牌或进入房间。
- 使用 `+` 和 `−` 修改数量。
- 使用 **移至备牌** / **移至主牌**，或拖动一行的 `⋮⋮` 手柄，在主牌和备牌之间移动卡牌。
- **备选** 会打开独立的大型管理弹窗，不长期占用套牌编辑空间。可以从数据库搜索中添加卡牌、调整数量，或每次在主牌与备选区之间移动一张。备选区会本地保存并导出，但只服务于编辑：不会登记进对局、不参与套牌合法性检测，也不是换备牌时的备牌。
- 单击卡名旁的缩略图，或系列/收藏编号按钮，可以更换印刷版本并预览该版本的准确卡图。预览走本地卡图缓存和目录下载，不会让界面直接向网站拉图。下载未完成时选择器会保持加载状态，卡图写入缓存后自动刷新，不会先显示「这个版本暂无可用卡图」。如果该印刷版本没有简体中文卡图，选择器会显示同一印刷版本的英文卡图，而不是借用其他印刷版本。某次下载超时会自动重试，不会因此让同一张牌的其他版本也无法拉图。还没有系列信息的卡牌会显示 **选择版本**。本地已经缓存的卡图会直接显示，不必等 **缓存卡图** 把路径写回套牌列表。
- 编辑法禁或指挥官套牌时，使用主牌旁边的 `☆`/`★` 指定或取消最多两名指挥官。被指定的指挥官仍留在原来的类别分组（通常是生物）里，并用指挥官标记标出，不再单独占右侧栏，卡图区使用整行宽度。
- 主牌默认按卡牌类别分组，并区分生物、鹏洛客、战役、神器、结界、瞬间、法术、地和其他；构筑法禁或指挥官套牌时不显示独立备牌区域。搜卡和衍生物管理留在主工具栏。

Hexproof 始终是一款手动牌桌工具。编辑器允许自由修改；当前数据库确认命名赛制中的牌数、备牌、重复张数、禁限牌或卡牌解析违规后，才会阻止该套牌用于相应房间。颜色认同只作提醒，无法可靠判断的卡牌文字例外仍由玩家负责。

## 10. 设置和卡牌数据库

设置页是分类列表。进入某个分类只改那一组选项；**返回**回到分类列表。

### 语言与显示

- **界面语言**切换菜单和应用程序文字。
- **卡牌语言和卡图**可以独立选择英文或简体中文卡牌显示。Forge 战场、堆叠、指挥官条和检视标题上的公开卡名跟随这项设置（本地目录有译名时显示中文）；菜单仍跟随**界面语言**。
- **卡图首选下载源**可选择自动（默认）、Scryfall 或 MTGCH，只影响以后尚未缓存的卡图。自动模式下，中文卡牌优先 MTGCH，英文卡牌优先 Scryfall。本地兼容卡图始终优先；首选来源缺图或连接失败时会自动尝试另一来源。中文模式始终先尝试中文卡图，再回退到英文卡图。
- Scryfall 标记为 `missing` 或 `placeholder` 的图片只是缺图占位，不会作为卡图使用；`lowres` 和 `highres_scan` 仍可使用。指定版本的简体中文记录只有占位图时，会改用该印刷版本的英文卡图，不显示“Localized Image Not Available”占位牌。
- 卡图解析策略升级后，兼容的本地文件仍会保留。客户端会在再次请求卡牌时用已安装数据库校验旧 Scryfall 映射，安全的记录会原地升级；只有无法确认安全的映射才会重新解析。因此删除并重新导入套牌，通常不会重新下载已经缓存的卡图。
- **优先复用本地已有的同卡卡图**默认开启。请求的印刷版本未缓存时，缓存卡图和房间卡图预加载可以复用本地同一张牌、同一牌面、同一卡牌语言的其他版本卡图。该功能只替代图片文件，不会改变套牌或服务器使用的印刷版本身份；在套牌编辑器中主动选择版本时，仍会下载该版本的准确卡图。关闭此选项会停止机会性的本地跨版本复用，但不会隐藏已经由 Scryfall/MTGCH 卡牌语言回退链选中的卡图。牌表条目没有系列或收藏编号时不存在需要保持的精确版本，因此即使关闭此选项，也会优先采用兼容的本地卡图。
- **界面缩放**以 5% 为步长，在 75% 到 150% 之间调整主题文字、控件、间距和对话框。**恢复为 100%**会还原默认比例。

### 应用更新

打开 **设置 → 应用更新**，对比**已安装版本**和**最新版本**，再选择**检查更新**。客户端会先向 GitHub Releases API 查询适用于此设备的最新稳定版。若该 API 被限流或无法访问，则改读 github.com 上公开的 `SHA256SUMS`。

现场检查失败时，会保留上次校验过的版本并标为**缓存**，状态为**检查失败**；这并不表示当前安装已是最新。下载仍会用 `SHA256SUMS` 校验安装包，再打开下载目录。替换便携版前请先退出 Hexproof。

### 下载系列卡图

打开 **设置 → 下载系列卡图**，按系列代码、系列名或补充包产品名搜索，再选择**下载产品卡图**。客户端会按当前卡牌语言和首选卡图来源，缓存该已安装产品中所有不重复的印刷版本和独立牌面；本地已有且兼容的卡图会保留。也可以从 **设置 → 卡图存储** 进入同一界面。不必先创建限制赛；系列现开或系列轮抓的报名大厅仍会为当前赛事产品提供同一操作。

### 卡牌数据库

Hexproof 只使用一个可搜索数据库：**Default Cards**。它包含搜索、印刷版本选择、收藏编号、衍生物和徽记所需的全部 Scryfall 印刷版本元数据，取代了以前 Oracle/Default 二选一的方式。

应用程序通常会下载 Hexproof 预先构建并压缩的 Default Cards 数据库。该数据库已经在同一个 SQLite 文件中合并了 Default Cards、当前 MTGCH 中文名称索引，以及精简的 Scryfall 简体中文印刷版本索引。替换现有数据库前，客户端会按照发布清单校验压缩文件和解压数据库的大小与 SHA-256。索引只保存卡图地址、版面和牌面身份，不包含卡图文件；卡图仍会在实际需要时下载并缓存。

### 下载或更新

1. 打开 **设置 → 卡牌数据库**。
2. 对比 **已安装版本**和**最新版本**；两处都会显示数据库构建日期和结构版本。需要时可选择**检查更新**手动刷新发布清单。
3. 选择**下载 Default**或**立即更新**。
4. 确认网络下载，并在数据库校验和安装完成前保持应用程序运行。

再次下载会执行更新。Hexproof 只下载官方预构建包，不会在玩家电脑上使用 Scryfall 或 MTGCH 现场重建数据库。仓库或发布包暂时不可用时，“最新版本”会显示为不可用，已有数据库仍会保留，并且仍可导入离线 `.sqlite`、`.sqlite.gz` 或 `.db` 数据库。

后续 Scryfall 查询如果发现数据库中缺失的简体中文印刷版本，Hexproof 会把经过验证的版本元数据写回同一个数据库，并单独缓存卡图；以后解析该版本时即可优先使用本地数据。

### 导入离线数据库

1. 准备 Hexproof `.sqlite`、`.sqlite.gz` 或 `.db` 数据库包，或者受支持的 Scryfall `.json`/`.gz` 批量数据文件。
2. 在 **Default Cards** 面板中选择 **导入…**。
3. 选择本地文件。
4. 等待验证、复制或原始数据索引完成。

官方 GitHub card-data 资源可直接导入 `hexproof-default-cards.sqlite.gz`。客户端会先解压再安装，和**下载 Default**相同。可分发数据包里的未压缩 `hexproof-default-cards.sqlite` 也可以导入。这两种文件都已经包含中文别名索引和精简中文印刷版本索引。

当前客户端要求卡牌数据库结构版本为 v10。该版本保留 Scryfall 的卡图状态，用于拒绝缺失图片和本地化占位图；也保留 v8 引入的 `legal`、`restricted`、`banned` 和 `not_legal` 赛制合法性状态。旧数据库不能直接导入；请下载当前数据库，或使用当前版本的发布工具重新构建。客户端会在替换已安装数据库之前明确报告结构版本不匹配。

该数据库包的 `import/` 中只有一个可以直接使用的 SQLite 数据库；`source/` 只保存用于复现构建过程的 Scryfall 和 MTGCH 原始输入；`manifest.json` 与 `SHA256SUMS` 分别用于描述和校验数据库包。直接导入 Scryfall `.jsonl.gz` 可以现场重建英文数据库，但不会自动合并旁边的 MTGCH 压缩包；MTGCH `.tar.gz` 也不能作为独立数据库导入。

导入过程是原子的：只有新数据库验证成功后，才会替换当前已安装的主要数据库。成功后，Hexproof 使用应用数据目录中的 `cards.sqlite` 安装副本，而不再依赖数据库包中的原文件。

### 导入 Forge 规则离线包

只有在本机托管 Forge 的玩家需要安装本地规则引擎。下载较慢时，可以获取适合本机系统的 `.hexproof-forgepack` 离线包（Windows x64、Linux x64 或 macOS Apple Silicon）。

1. 打开 **设置 → 本机 Forge**。
2. 选择 **导入离线包**，直接选取文件，无需解压。
3. 等待校验、安装完成，显示“本地规则引擎已就绪”。

离线包已包含 Forge 和 Java，导入时无需联网下载。请保留至少 1 GiB 可用空间。离线包必须与客户端所需的规则版本及本机系统匹配；损坏或不匹配的文件会被拒绝，导入失败或取消不会替换已有运行环境。安装完成后不再依赖原始离线包。加入对局仍需连接服务器。

准备、导入或本机托管失败时，可在同一窗口点击 **导出托管诊断**，将保存的 JSON 文件和触发问题的操作步骤一起发给维护者。报告包含系统和版本信息、带时间的安装及托管记录，以及具体错误类别。最近记录会保存在本机，重启客户端后仍可导出；请尽早导出，以免被后续操作替换。报告不包含套牌、卡牌、连接凭据、服务器或镜像地址、本地路径和引擎原始输出。导出只保存本地文件，不会自动上传。

### 启用玩家直连（P2P）

创建双人 Forge 房间并选择 **由本机托管** 后，等待房间左下角会把托管状态、紧凑 **P2P** 控件和 **下载和诊断** 收成一组。进入对局后，右上角 **设置** 里有同样的直连控件，以及完全控制、日志/聊天和阶段停顿；过牌板位于窗口右下角；双人对局中卡牌会避开这一角，打开选择时不会移动卡牌。较高的选择会覆盖在战场上，可点旁边的 **隐藏选择** 查看下面的卡牌，再点 **显示选择** 返回。Forge 仍在处理上一个操作时，点击高亮的卡牌或玩家只会显示 **等待游戏处理**，不会重复发送。横置的牌保持正放，图案变暗，图案中间有一个大的横置符号；力量、防御力和指示物仍然清楚。牌换到新位置后，立即就能在新位置点击。一叠牌的角标会显示张数，以及其中新进场的张数。同名牌里横置的那些单独成下一叠。点一叠牌会使用你点中的那张；如果这叠牌彼此不同（例如一张正在阻挡），这叠牌会展开让你选择。按回车或点角标也会展开，按 Esc 收起。一叠相同的地里，点已横置那张露出的一角可以撤销该法术力。攻击者只有一个合法对象时，点一下就宣告攻击。**全部攻击**会把尚未指定的生物都指向防守玩家；有多名玩家可选时会先询问；只能攻击鹏洛客或战役时该按钮不可用。阻挡者只有一个合法攻击者时，点一下就宣告阻挡。**全部阻挡**会指定每一个这样的阻挡者；能阻挡多名攻击者的生物留给你自己选。三人与四人牌桌的选择盖在角落上，不再把牌挤开；较高的选择同样可以用 **隐藏选择** 看下面的牌。日志关闭时，阶段条下面会保留最近两条公开记录，点这一条即可打开日志。法术力还在支付时，可以继续点地牌把它们排进队列，也可以从同一叠里排多张，每张牌上有序号；如果仍是同一次支付，游戏会按顺序使用这些地。出错或超时会清空队列。牌会滑到新位置，标记会在区域间飞过；点击仍然立刻落在牌的新位置上。`HEXPROOF_MOTION=0` 可以关掉这些动画。**显示日志 / 聊天** 会在牌桌上打开一块可拖动的浮层，拖标题移动，拖右下角调整宽高，右键标题恢复默认大小和位置；战场和过牌区不会被挤开。

**设置 → 对局 → 优先使用 P2P 直连** 默认开启。直连会向对方共享网络地址，并使用 STUN 服务；双方真人玩家都开启后才会尝试连接。状态会先显示等待对方，再显示连接进度或 **直连已建立**。直连失败时自动使用服务器中转，可点 **重试直连** 再次尝试，或点 **仅使用中转** 关闭直连。该偏好会保存，换房间或重启后继续沿用；可点 **启用直连** 再次开启。公共服务器仍然必需。AI 练习、观战者和服务器托管房间不显示该选项；旧服务器不支持直连时，会显示禁用按钮及原因。

### 保存优先权模式与停点

在 **设置 → 对局** 中，可以明确选择 **智能优先权**（默认）或 **完全控制**，并分别设置自己回合与其他玩家回合的停点。牌桌内的设置仍可修改同一份偏好，两处修改同步保存，重新开局或重启客户端后也会保留。临时让过本回合或堆叠不会改动保存的优先权模式。

### 在 Forge 中查看与选择卡牌

找地、检视牌库或从对手展示的手牌中选牌时，完整可见牌面与选择操作会放在同一个窗口，不再先确认一次展示。默认显示全部可见牌；开启 **仅显示可选牌** 后，只保留当前效果允许选择的牌。标注 **不可选择** 的牌仍可查看，但不能选中。搜索或切换筛选会保留已选牌，下一次选择会恢复默认显示。

## 11. 牌桌布局

默认牌桌包含：

- 可选的左侧栏，其中包含房间控制、公开游戏日志和聊天；
- 可选的公共堆叠/展示区域；
- 每名玩家各自的战场；
- 底部的本地手牌和本地区域面板；
- 每位远端玩家各自独立、可拖动的悬浮区域面板；
- 无额外边框的悬停卡图预览。

每块战场的左上角都会始终显示对应玩家名字；即使没有展开远端区域面板，也能直接确认战场属于哪位玩家。

多人指挥官牌桌完成加载时，服务器会为每位已入座玩家公开投一个 d20；同点玩家继续重投，游戏日志中从大到小的最终结果就是完整回合顺序。每位玩家仍会在本机看到自己的战场位于本地一侧，其余玩家按这个顺序沿牌桌顺时针排列；观战者会看到先手玩家位于本地一侧。新建一局指挥官游戏会重新投骰，使用**重新开始游戏**则保留当前顺序。

为了让战场始终是视觉主体，Hexproof 把许多手动牌桌命令放在右键菜单、拖放目标和悬停提示中，而不是常驻按钮上。找不到某项操作时，先把鼠标悬停在相关卡牌或牌堆上，再尝试右键。单张卡牌的菜单和周围空白区域的菜单有意设计为不同内容。

使用牌桌上的 **设置**可以：

- 显示或隐藏游戏日志/聊天侧栏；
- 显示或隐藏公共堆叠/展示区域；
- 选择显示 0 至 7 个本地玩家指示物槽位。

隐藏左侧栏后，可以使用 **显示游戏日志**恢复。在指挥官对局中，可以切换 **总览布局**和**主战场**，也可以选择某个战场作为主视图；再次点击当前主战场的按钮会恢复总览布局。每位对手的墓地、放逐区、指挥官区和牌库操作位于其独立的悬浮区域面板中；使用对应战场的 `▾`/`▴` 显示或隐藏。多个面板可以同时打开。面板默认以紧凑的两行布局显示在对应玩家战场的右下角；生命和手牌数量继续显示在战场标题中，不会在面板里重复。拖动玩家名字可以单独移动该面板到日志列或窗口中的其他空白位置，右键玩家名字可恢复到该战场右下角。

游戏日志标题区域中的比例悬浮球只用于调整指挥官战场的卡牌大小，不会占用战场布局空间；总览与主战场通过各战场自身的主战场按钮切换。悬停或单击悬浮球可展开比例控制，鼠标离开后会自动收起。可以把悬浮球拖到牌桌窗口中的其他位置，右键悬浮球会恢复默认停靠位置；隐藏日志后，默认位置会切换到窗口右侧中部。自动模式在四人总览中使用 70%，在三人总览中使用 80%，在主战场中使用 100%。可以使用 `−`/`+`，或把鼠标放在战场上并按住 `Ctrl` 滚动，在 50%–125% 之间以 5% 为步长调节。总览和主战场/普通布局的大小会分别保存在本客户端；单击百分比按钮可恢复自动大小。悬停大图不会随战场卡牌缩小。

游戏日志记录公开的手动操作。聊天输入框发送的消息会明确公开给牌桌中的所有人；可以单击**发送**或按 `Enter`。

### 回合、战斗与规则提醒

- 左侧回合控制器显示当前玩家和 11 个共享步骤。只有当前回合玩家可以选择步骤、进入下一阶段或结束回合。
- 每位玩家的战场信息区显示各自已开始的回合数，包含正在进行的回合。开局先手为 1，其他玩家为 0；轮到谁就增加谁的计数，重连保留，下一局或重新开始游戏时重置。
- 在宣攻阶段选择一张或多张自己操控的永久物后，通过右键菜单攻击玩家或选择对方战场永久物；宣阻阶段选择阻挡者后，再指定一个正攻击自己或自己永久物的攻击者。
- 提交声明前，弹窗会列出所有选中卡牌。每个攻击者都可以单独保留或取消**横置**；声明和所选横置会由服务器一次完成。已横置卡牌或牌面类型不是生物的卡牌会显示提醒，但卡牌效果可能允许该操作，因此仍可继续。
- 对咒语或异能，可以右键选择自己操控的一张或多张战场卡牌并使用**选择目标**，直接指定玩家，或再单击一张战场卡牌。自己拥有的堆叠卡牌也可通过 `◎` 使用相同功能。箭头只是公开提示，不检查目标合法性；可以使用**清除目标**移除。
- 回合控制器中的 **地牌 · N** 是本回合公开记录的地牌使用次数。当前回合玩家可以用 `−`/`+` 校正；它只是协调记录，不是规则上限，并会在下一回合重置。
- 公共堆叠仍有卡牌或有人选择**请等待**时，推进阶段或结束回合会要求确认。结束回合时，如果手牌超过七张也会提醒。
- 生命为 0 或更低、牌库为空以及手牌超过七张会使用警告样式。这些只是提示；Hexproof 不会自动判负，也不会强制执行手牌上限。

## 12. 卡牌和区域的核心操作

### 鼠标与右键操作速查

| 位置 | 左键 / 双击 | 右键 / 拖动 |
|---|---|---|
| 战场卡牌 | 单击选择；`Ctrl`/`Shift`-单击切换多选；双击自己操控的卡牌进行横置/重置 | 右键打开卡牌操作，包括对自己拥有的卡牌使用**结附到…** / **解除结附**，以及对受控卡牌使用**选择目标**；拖动自己拥有或操控的卡牌来调整位置或移至有效区域 |
| 自己战场的空白处 | 在适用时清除普通选择 | 右键使用**整理战场**、**全部重置**、**创建衍生物**和**投降** |
| 手牌中的卡牌 | 悬停查看大图 | 右键使用**使用地牌…**或精确移动；横向拖过其他手牌可在本地排序，拖出手牌区域则可移至战场、公开区域或共享区域 |
| 手牌空白处 | 不执行卡牌操作 | 右键使用**选择并批量移动手牌…**、**展示手牌/收回手牌**、**随机弃一张牌**、**弃掉全部手牌…**和**调度** |
| 自己的牌库 | 左键不会抓牌 | 右键打开牌库命令；从卡背拖动未知的牌库顶牌 |
| 对手的牌库 | 左键单击不执行操作 | 先用对手战场上的 `▾` 打开该玩家的悬浮区域面板，再右键申请完整搜寻、查看牌库顶牌或查看牌库顶 X 张 |
| 墓地、放逐区或指挥官区 | 单击浏览；悬停当前可见顶牌查看大图 | 从自己的墓地/放逐区拖动符合条件的顶牌；在法禁或指挥官对局中可直接拖动自己右侧指挥官区卡图中的任一张牌；也可在区域浏览器内右键卡牌 |
| 牌库搜寻中的卡牌 | 单击卡牌行查看大图；单击复选框选择 | 右键对单张卡牌或当前选中组执行目标区域操作 |
| 公共堆叠/展示卡牌 | 堆叠卡牌会显示拥有者的玩家名；单击自己拥有的卡牌显示精简操作按钮；堆叠卡牌还会显示 `◎` **选择目标** | 拥有者可以把它拖回有效区域 |

悬停可见卡牌会显示不占用固定牌桌空间的卡图大图。战场牌部分重叠时，把鼠标移过各张牌露出的部分即可切换对应大图。菜单项被禁用通常表示当前玩家没有该牌的拥有权或操控权、来源/目标区域无效、当前对局不可操作，或者查看者是观战者。

### 战场卡牌

- 拖动自己拥有或操控的卡牌，可以调整位置或将其移动到有效区域。
- 把自己拥有的卡牌放到另一名玩家的战场，会让该战场对应的玩家成为操控者，但不会改变卡牌拥有者。各玩家视角中的卡图仍保持正向显示。
- 对于战场上牌面朝下的卡牌，只有当前操控者可以查看其身份、选择显示牌面或将其翻回正面/再次翻为背面。如果该牌由另一名玩家拥有，原拥有者仍然只能看到卡背。
- 新进入战场的正面牌会按类别辅助定位：地贴着本地玩家一侧的边缘；生物从中间向左右两边扩展；远侧从左到右分别放置结界/未知牌、神器以及鹏洛客/战役。手动放上战场的瞬间和法术使用独立的法术暂放行，不再与永久物混在一起。多面牌按进入战场时选择的牌面分类。已有战场牌不会因此自行跳动，牌面朝下的牌只使用中立辅助区，玩家仍可自由拖动任何自己操控的牌。
- 只有可互换的同名地和生物会以轻微斜向错位的方式紧凑叠放，即使它们来自不同系列；每张牌仍露出一部分以便查看大图、选择或拖动。有指示物、是指挥官、由其他玩家拥有、参与攻击/阻挡或附着关系、牌面/横置/衍生物状态不同、牌面朝下，或不属于地和生物的牌都会保持独立。
- 展开后的对手墓地和放逐区也是符合条件的自有/受控卡牌拖放区域，但卡牌最终总会进入其拥有者的墓地/放逐区；当前操控者和实际松手的牌堆不会改变归属。
- 双击自己战场上的卡牌将其横置或重置。
- 单击卡牌进行选择；`Ctrl`-单击或 `Shift`-单击可以在多选中切换该卡牌；普通单击会开始一组新选择。
- 右键单击卡牌可以：
  - 在可用时选择双面牌的牌面；
  - 添加或设置数量指示物；
  - 添加或编辑有名称的异能指示物；
  - 对自己拥有的卡牌使用**结附到…**再单击另一张战场牌，或**解除结附**。同一车道上的结附会叠在宿主上并跟随拖动；结附到另一玩家的永久物时，来源仍留在操控者车道，画面叠在目标上，不改变操控者；
  - 将单张卡牌移至手牌、墓地、放逐区、牌库顶、牌库指定位置或牌库底；
  - 将多选卡牌移至各自拥有者的手牌、墓地、放逐区，按选择顺序/随机顺序移至牌库顶/牌库底，或洗入整个牌库；
  - 对自己操控的一张或多张战场卡牌使用**选择目标**，直接选择一名玩家或再单击一张战场卡牌；
  - 使用**清除目标**移除所选来源的普通目标箭头；
  - 创建该卡牌的衍生物复制。
- 把多牌面的卡牌移到战场时会要求选择牌面；之后仍可从右键菜单修改。
- 战场徽标分别显示数量指示物数值、小圆形 `T` 衍生物角标、`♛` 指挥官状态以及 `◆` 异能指示物；悬停 `T` 显示“衍生物”，悬停 `◆` 可以查看名称和数值。
- 单选一个由自己操控的永久物后，按 `-` / `=` 可以把它的数字指示物减少/增加 1；数字指示物不会低于零。
- 当卡牌所在战场的操控者与不可变的拥有者不同时，会显示 `◇` 拥有者标记；悬停可查看拥有者。
- 右键单击自己的空白战场，可以使用 **整理战场**，把当前战场按上述类别重新排列。该操作一次提交全部位置；也可使用 **全部重置**、**创建衍生物**以及多人游戏中的 **投降**。

### 手牌

- 横向拖动一张手牌经过其他手牌，可以改变仅当前客户端可见的显示顺序；其他
  手牌会平滑让位，房间状态刷新后仍保留该顺序，新抓到的牌会追加在末尾。该
  操作不会发送给服务器，也不会写入游戏日志。
- 将卡牌从手牌拖到战场或允许接收卡牌的公开/共享目标。
- 当前回合玩家可以在手牌右键菜单中使用 **使用地牌…**，选择牌面、查看提醒，并由服务器一次完成进入战场和公开次数加一。已经记录过地牌使用、当前不是主阶段、堆叠不为空或所选牌面未识别为地牌时会提醒，但卡牌效果或牌桌约定可能允许，因此仍可继续。
- 右键单击手牌，可以将其移至战场、墓地、放逐区、牌库顶、牌库指定位置或牌库底。
- 普通右键移动和拖放不会增加地牌使用次数；需要时可用回合栏中的 `−`/`+` 校正记录。
- 右键单击空白手牌区域，可以使用 **展示手牌/收回手牌**、**随机弃一张牌**、**弃掉全部手牌…**和 **调度**。随机弃牌由服务器选择；弃掉全部手牌会先要求确认，再以原子操作移动整手牌。
- **展示手牌**会把当前全部手牌公开到共享区域中以该玩家命名的分区；**收回手牌**会以原子方式把该玩家展示的所有卡牌返回手牌。
- 手牌过多而无法全部显示时，使用手牌区域的横向溢出控制。

### 自己的牌库

左键单击牌库不会抓牌。

- 从牌库卡背拖动，可以把未知的牌库顶牌移至手牌或战场等有效目标。
- 把符合条件的卡牌放到自己的牌库牌堆上，会将其置于该牌拥有者的牌库顶。
- 右键单击牌库可以：
  - 抓 X 张牌；
  - 洗牌；
  - 搜寻牌库；
  - 查看备牌；
  - 查看牌库顶牌；
  - 查看牌库顶 X 张；
  - 将牌库顶 X 张置入墓地；
  - 将牌库顶 X 张置入放逐区。

完整牌库搜寻界面只对获得授权的查看者可见：

- 可以使用中文或英文卡名、卡牌类别筛选；
- 单击卡牌行会更新右侧大图，只有单击复选框才会改变选择状态；
- **全选**只会选中当前筛选结果中的所有卡牌；
- 选中多张牌后，可以在**已选卡牌顺序**中使用箭头明确命令顺序；
- 选择目标区域以及是否在公开游戏日志中展示所选卡名，然后单击**完成搜寻**；
- 右键单击某张牌可以立即选择目标区域；如果该牌已经属于当前多选，操作会应用于整组选中卡牌；
- 普通目标区域包括手牌、战场、墓地和放逐区；只有牌库顶/牌库底在右键菜单中另外提供保持顺序或随机顺序的版本；
- 把多张选中卡牌置入战场时，它们会在相邻的确定位置一起铺开。

**搜寻或查看牌库不会自动洗剩余牌库。** 关闭自己的完整牌库搜寻后，Hexproof 会询问是否立即洗牌；如果该卡牌效应不要求洗牌，选择取消即可。如果所选卡牌要放回牌库顶或牌库底，这次选择会在放置前处理：确认后会先发送洗牌、再放置所选卡牌，取消则不洗牌并直接放置。**查看牌库顶牌**和**查看牌库顶 X 张**不会出现该提示。**查看牌库顶牌**是私人操作，可以右键把该牌移到其他区域，也可以明确放回来源牌库顶或置于来源牌库底，以完成占卜 1 等操作；单张牌不会显示没有实际区别的随机顺序选项。在**查看牌库顶 X 张**中，每张牌都可以分别指定去向：自己的手牌、自己的战场（可选择牌面朝下）、来源玩家的墓地或放逐区，以及来源牌库顶或牌库底。箭头决定放回同一牌库端的牌之间的相对顺序，牌库顶和牌库底两组也可以分别随机排列。这样可以在一次原子操作中结算“展现迭代”等去向不同的效果。把不需要的牌指定到牌库底、其余指定到牌库顶就是普通占卜，没有单独的占卜菜单。

### 申请查看对手的牌库

为了减少常驻按钮，这项操作直接放在对手牌库牌堆上：

1. 在对手战场标题处使用 `▾` 打开该玩家的悬浮区域面板。
2. 右键单击对手的牌库牌堆，选择**搜寻牌库**、**查看牌库顶牌**或
   **查看牌库顶 X 张**；左键单击不会发出申请。
3. 牌库拥有者会收到带申请者姓名的模态对话框，并选择**允许**或拒绝。
4. 允许后，只有申请者会收到完整牌库或所申请的牌库顶范围；其他玩家和观战者仍然只能看到牌库数量/卡背，以及不含卡牌身份的公开日志。
5. 完整搜寻和查看牌库顶牌会提供各自允许的普通目标区域；在查看牌库顶 X 张时，每张获准查看的牌都必须指定一个去向。手牌和战场去向属于申请者，墓地、放逐区和牌库两端属于来源玩家。公开日志只记录查看数量和使用了几个目的区域，不会记录卡牌身份。

授权有效时间很短，只绑定该申请者和来源牌库，并且只能使用一次。以后再次搜寻需要重新申请。拒绝、过期、断线或申请信息不匹配都不会泄露任何卡牌身份。

### 墓地、放逐区、指挥官区、堆叠和展示

- 单击任意玩家的墓地、放逐区或指挥官区以浏览可见卡牌。墓地和放逐区浏览器提供复选框及**全选可见牌**，其范围遵循当前筛选条件；全选后变为**取消可见牌选择**。点击**移动所选**或右键已选卡牌，可将整组牌一次移动；右键未选卡牌仍只操作该张。开启**逐张显示**可选择同版本的特定副本。小窗口可通过**预览**／**牌张**切换内容，底部移动按钮始终可用。
- 结算**坚忍**时，由受影响的玩家打开自己的墓地、清空筛选、全选可见牌，再选择**移动所选 → 牌库底 · 随机顺序**；原有牌库的顺序保持不变。处理倾曳后剩余牌时，只选择相应的放逐牌。按顺序放置采用勾选顺序；**洗入牌库**会连同原有牌库一起洗牌，是另一个独立选项。
- 将自己墓地或放逐区当前显示的顶牌拖到有效目标。
- 在墓地或放逐区浏览器中右键卡牌，可以在允许时把它移到操作玩家的战场、墓地、放逐区或牌库顶。若来源牌堆属于另一名玩家，卡牌不会立即移动；该玩家会收到包含申请者、来源区域、数量和目标区域的确认请求，只有批准该次短时、一次性请求后才会执行。拒绝、过期或断线都会取消操作；成功后的游戏日志会明确写出来源玩家和来源区域。墓地/放逐区始终按卡牌拥有者归属，只有所有受影响卡牌均属于本地玩家时，才可使用移至手牌或牌库相关操作。
- 自己的指挥官区还允许通过右键把卡牌移到战场、手牌、墓地或放逐区。使用**施放指挥官**会把所选指挥官移到公共堆叠，并且只增加该指挥官自己的税；其他玩家的指挥官区只能查看。
- 从自己牌库的右键菜单打开备牌。备牌内容是私人的；浏览器可以把卡牌移到战场、手牌、墓地或放逐区。
- 把符合条件且由自己拥有/操控的卡牌拖入公共区域，以表示堆叠中的咒语或手动展示。牌库中的卡牌以及已经位于公共区域的卡牌不能再次拖入。
- 单击自己拥有的公共卡牌，会显示精简的 `↗` 战场、`†` 墓地和 `⌂` 手牌按钮；自己拥有的堆叠卡牌还会显示 `◎` **选择目标**，可以指定任意在座玩家或战场卡牌。也可以把公共卡牌拖到有效目标。目标箭头只是公开提示，不检查卡牌文字或目标合法性；来源离开堆叠时会自动清除。只有卡牌拥有者可以把它移出，堆叠结算完全由玩家手动完成。
- 手牌右侧的指挥官卡图牌堆是自己唯一的指挥官区控件。单击可以浏览；可以直接把其中任一名指挥官拖到战场、手牌、墓地、放逐区、牌库或共享区域，也可以把符合条件的指挥官拖回该牌堆。普通拖动始终只是手动移动，不会被计为施放；仍可使用玩家名称与生命值下方的 `−` 和 `+` 控件校正指挥官税。

### 生命和玩家指示物

- 使用生命值旁的 `−`/`+` 逐点调整。
- 选择生命值可直接输入准确数值；允许负生命。
- 第一次单击某个指示物圆点会选中它。
- 选中后，左键增加 1，右键减少 1。
- 使用下方快捷键重命名指示物或设置准确数值。
- 牌桌设置决定七个同步指示物槽位中显示多少个。隐藏槽位仍会保留名称和数值。

## 13. 调度、衍生物、投降和换备牌

- **调度**会把当前手牌洗回牌库、洗牌、重新抓至多七张牌，增加公开调度次数并记录日志。Hexproof 不会执行伦敦调度的牌库底放牌规则。
- **创建衍生物**会搜索已安装且包含衍生物的数据库，并在战场上创建使用英文卡图的衍生物。衍生物离开战场后会消失。
- **投降**需要确认：
  - 通用 1v1 中，对手获得本局或整场比赛胜利。
  - 法禁中，对手同样获得本局或整场比赛胜利。
  - 指挥官中，投降玩家被淘汰，其余玩家继续游戏。
  - 单人测试没有投降操作，应直接结束测试。
- 比赛结束后会打开结果对话框。**返回房间**会保留座位和已登记的套牌，但清除准备状态、游戏状态和比分。

通用 1v1 BO3 中，如果比赛尚未结束，会打开五分钟换备牌工作区，铺满牌桌、不再套一圈边框：

- 按卡牌类别铺开完整的已登记主牌和备牌；
- 相同卡牌堆叠，并显示数量标记；
- 悬停显示卡牌大图；
- 在主牌和备牌之间拖动一张卡牌；
- 双方都准备后立即开始下一局；
- 超时会放弃未完成的编辑，并恢复上一局的主牌/备牌分区。

法禁 BO3 使用同一个五分钟局间界面，但它只用于双方确认准备。主牌与
备牌之间的移动会被禁用，下一局继续使用原来的已登记套牌。

### 服务器赛事

**赛事**浏览器同时显示构筑和限制赛瑞士轮比赛；Cube 自由对战房间只显示在
**浏览大厅**的房间列表中，不再与赛事混在一起。
构筑比赛可以从标准、先驱、摩登、薪传、特选、纯铁和法禁中选择赛制。
在主办人开始赛事前完成报名与签到；取消报名后，签到和取消报名操作会消失，
并重新显示报名按钮。

限制赛的使用方式如下：

- 通过**赛事 → 创建赛事**选择**系列现开**或**系列轮抓**，主菜单不再单列“限制赛玩法”入口。
- 主菜单的**模拟开包**支持离线使用；限制赛创建页面也保留模拟器快捷入口。
  本地模拟开包不会生成可用于对局的牌池。模拟开包会先展示
  卡背，并把稀有和秘稀牌排在最后；点击哪张卡背就会翻开哪张，也可以随时选择
  **全部揭示**或**跳过动画**。模拟器支持按系列代码、本地化系列名称或补充包
  产品名称搜索。在**设置 → 外观**中可以关闭开包动画，不会改变开包结果。
- 创建限制赛比赛时，可以按系列代码、本地化系列名称或补充包产品名称搜索系列。
- 一个人练习轮抓时，进入**模拟开包 → 模拟轮抓**，也可使用轮抓赛事创建页面的
  **模拟轮抓**入口，无需连接服务器。选择已安装的系列或已保存的普通 Cube，
  设置 2～8 个座位（默认 8 个，包括自己），其余座位由机器人自动选牌。
  每人三包，依次向左、向右、向左传递；每手和最后一张都需自己确认，选牌不限时。
  Cube 每包 15 张，牌池至少需要“座位数 × 45”张。机器人只根据稀有度、已抓颜色和
  法术力曲线进行基础判断，不评估单卡强度或配合。
  完成后可练习组牌，主牌至少 40 张，普通基本地可自由加入；点击**保存到套牌库**
  会创建一副自定义套牌，未选入主牌的轮抓牌成为备牌。修改后可**保存新副本**。
  返回其他页面后可以继续，练习进度保留至关闭应用；**重新轮抓**会确认放弃当前
  未保存进度，已保存的套牌不受影响。
- 在系列现开或系列轮抓的报名大厅中，点击**下载产品卡图**，可以在开赛前缓存该产品中所有不重复的印刷版本和独立牌面。同一功能也可以在 **设置 → 下载系列卡图** 中单独使用，不必进入赛事。进度条会显示完成数量和不可用卡图数量；MTGCH 系列索引失败时会自动继续逐卡回退，下载不会阻止签到或开赛。
- 数据库 schema 10 中已安装的系列产品会尽量使用 MTGJSON 的精确配牌规则；
  如果旧数据库或不完整数据库缺少该规则，界面会明确标记为按稀有度近似配牌。
- **系列现开**固定为每名已签到玩家打开 6 包补充包，至少 2 名已签到玩家即可开始。
- **系列轮抓**至少有 2 名已签到的真人玩家即可开始，人数上限为 2–8 人。每人轮抓 3 包，并按左、右、
  左的顺序传包；选牌可以在私人队列中等待，断线重连后会恢复当前包和此前选牌。
  轮抓界面会持续显示你此前抓到的所有牌，并以自己位于下方的实体牌桌视角展示
  座位，明确标出当前牌包要传给谁、下一包会从谁那里传来。窄窗口下，座位和此前
  抓到的牌会移到当前牌包下方，两个区域都可以正常访问。
- 在普通**套牌库**导入或编辑套牌时选择 **Cube** 赛制；“数量、牌名、系列、
  收藏编号”会组成一个完整牌池，没有单独的 Cube 导入入口，也没有备牌区。
  在**创建房间**中像摩登或指挥官一样选择 **Cube**，再选择这副 Cube 赛制套牌。
  这里创建的就是**自由对战**房间；需要安排轮次与排名时，使用独立的
  **赛事 → 创建赛事 → Cube 轮抓**入口。两种模式的人数上限均为 2–8 人。
  每人轮抓 3 包、每包 15 张，并按左、右、左传包；2 人时两个方向都指向同一位
  对手，牌包即在两人之间往返。Cube 需要为设置的每个座位
  准备 45 张实体牌（2 人为 90 张，8 人为 360 张），同一张实体牌不会进入两包。
  Cube 最多可导入 10,000 张实体牌和 5,000 个不同印刷版本条目；该限制与普通
  构筑套牌更小的导入安全上限相互独立。
- 组牌阶段会同时显示**主牌**和**备牌 / 可用牌池**两个区域；点击卡牌即可把该张
  实体牌移到另一侧。主牌至少需要 40 张；平原、海岛、沼泽、山脉和树林可以
  不限量加入，荒野和其他特殊基本地必须来自牌池。留在可用牌池中的牌成为备牌。
  工作区上方可以选择按**法术力值**、**颜色**、**卡牌类别**或**名称**重新整理
  两侧卡牌，不会改变套牌内容。颜色、类别和法术力值筛选会同时作用于可用牌池；
  例如依次选择蓝色、生物和法术力值 3，只会显示同时满足三项的牌。清除筛选即可
  恢复完整牌池。界面会把更多空间留给可用牌池，主牌以紧凑面板持续显示并分别
  统计地与非地。默认按所选非地牌费用中的有色法术力比例自动补充基本地，
  将主牌补至 40 张，并计入已经从牌池选中的地牌。增删卡牌后建议数量会自动
  更新；展开**基本地**可查看和调整。手动修改数量后会退出自动模式，重新勾选
  **自动补充基本地**可恢复。无法确定有色法术力需求时，需要手动选择基本地。
  自动分配是组牌起点，不代表最优法术力基础。分组资料从本地精确印刷
  版本数据库读取；缺少资料的牌仍可选择，并会归入**未知**。
- Cube 房间使用入座和**准备**，没有赛事报名或签到。房主创建后自动入座，其他
  玩家通过**浏览大厅**或房间码加入。至少两人且所有已入座玩家都在线并准备后，
  房主可点击**开始轮抓**。轮抓和组牌期间，**房间 / 聊天**可以查看席位进度和
  聊天。轮抓前普通玩家离开会释放座位；轮抓开始后离开界面会保留其牌池，以便
  稍后回来继续。房主离开则需要确认关闭整间房间。
- **指挥官 Cube**支持 2～8 人轮抓。人数上限为 2～4 人时，默认每人 6 包、
  每包 20 张；房主可以选择 3／4／5／6／8 包，以及逐包抓或双包并抓。双包模式
  每包分别选 2 张，一次确认 4 张，并一起传给下家。传递方向按批次交替；奇数
  包数的最后一包单独抓。5～8 人房间采用每人 3 包、逐包打开、每次选 2 张。
  所有人数配置都可输入**每包 10～40 张**，默认为 20 张；最后剩余的 1 或 2 张
  自动收取。创建时会显示所需牌数，牌池不足时不能创建，创建后规则固定。按默认
  每包 20 张计算，六包每人获得 120 张，三包获得 60 张。组建至少 60 张、包含
  1～2 名指挥官的套牌。
- 指挥官 Cube 组牌时，**固定可选牌**提供牌池外的**阳光戒、指挥塔、秘法印记**
  各一张，可以逐一添加或移除。只有选中的牌计入套牌，不占用 Cube 牌池，重连
  后会保留选择。基本地和原有的五彩吹笛人兜底仍可使用。
- 所有参战玩家提交后，会自动进入分配好的锁定套牌房间，点击**准备**即可。
  八人分成两桌四人，五／六／七人分别分为 3＋2、3＋3、4＋3；2～4 人同桌。
  首局无需另行邀请或接受邀请。
- 普通 Cube 只有两名参战玩家时，也会在双方提交后直接进入准备房间。退出本次
  对战的玩家和观众留在原房间，已提交后掉线的玩家仍保留位置。自动入桌不会自动
  准备。如果提交后又修改了套牌，进入前会要求确认是否放弃尚未提交的修改，
  不会无提示地丢失编辑。
- 更多人的普通 Cube，以及后续的**自由对战**，仍可选择对手。点击空闲玩家
  旁的**邀请对战**，对方**接受邀请**后，双方才能**进入对战**；邀请可以拒绝或
  撤销，已接受但尚未打开牌桌的配对也可以取消。不安排瑞士轮，不计排名，也不
  需要房主指定对手。关闭牌桌后双方可重新选择对手。未分配对局时可通过
  **调整套牌**返回原牌池修改，修改后请提交再选择对手；邀请或对局期间会锁定
  组牌。收到邀请不会删除尚未提交的编辑，拒绝或取消邀请后可继续修改。发送或
  接受邀请、进入对局、观战及离开房间前，如果仍有未提交修改，会要求明确确认
  放弃修改，不能直接沿用旧套牌而无提示地丢失编辑。未参与其他邀请或对局的
  玩家也可**观战对局**。
- 瑞士赛中，所有参赛者提交套牌后，由主办人发布第一轮。系列现开、系列轮抓和
  瑞士赛模式的 Cube 轮抓使用瑞士轮配对、赛果确认、排名和轮次推进。服务器会按照
  参赛人数推荐轮数；2 人赛事进行 1 轮，3–8 人赛事进行 3 轮瑞士轮。
- 进入限制赛配对房间时，服务器会自动装入此前提交的赛事套牌，不需要也不能从
  本地套牌库重新选择。看到**限制赛套牌已锁定**后，点击**准备**即可开始对局。
- 随机生成、实体卡牌实例、传包队列、牌池和组牌来源检查都由服务器负责；
  配对牌桌仍由玩家手动执行卡牌规则。

比赛进行期间，配对房间使用的牌表保持私密。最后一轮瑞士轮结束后，可以在
**牌表**分页查看所有参赛者在配对房间中登记过的牌表。**查看牌表**会按类别
展示卡图，悬停可看大图；**导出**可复制或保存与套牌库相同的
`Deck` / `Sideboard` / `Commander` 文本，便于再导入。配对房间的牌桌对局
结束后，**报告**会预填该牌桌比分（含平局局数）；提交前仍可修改。已确认的
比赛结果才是积分权威来源。

## 14. 日志保留

客户端已移除回放列表、播放界面及相关快捷键。对局中的实时日志和聊天仍可
正常使用。服务器已有存档、保留策略及经过隐私过滤的公开日志接口不变；移除
播放功能不会删除服务器历史数据。存档仍按管理员设置到期清理，默认保留七天。

## 15. 键盘快捷键

快捷键作用于当前活动的 Hexproof 窗口。当文本输入框或模态编辑器需要键盘输入时，相应快捷键会被抑制。选牌快捷键只会在手牌或战场二者之一存在选中内容时生效；如果两个区域同时残留选中状态，移动操作会主动拒绝执行，避免误移卡牌。

打开**设置 → 键盘快捷键**，可以搜索并修改所有应用、牌桌和选牌
操作。点击**更改**后按下一个组合键；按 Backspace 或 Delete 可以取消该
操作的按键绑定。如果新按键已经分配给其他操作，Hexproof 会拒绝保存并显示
冲突的操作名称。可以单独恢复某项默认值，也可以用**全部恢复默认**重置所有
操作。修改只保存在当前设备并立即生效；牌桌内的 `F1` 帮助会显示当前实际
绑定。鼠标手势和手牌焦点导航属于固定交互，不在可重新绑定的键盘操作范围内。

## 16. 隐私和运行说明

- 房间服务器受信任，并持有完整的套牌、手牌和牌库身份，以便权威地洗牌和同步隐藏区域。
- 客户端接收按照身份投影的数据。对手始终只能收到其他玩家隐藏区域的数量或牌背。观战者默认同样如此；房间可以明确允许观战者查看当前手牌，但该权限不包括牌库、备牌、私人搜索、牌面朝下的战场卡牌、日志或回放。
- 卡图文件保留在各客户端自己的本地缓存中。
- 房间密码、断线重连凭据和传输连接 ID 不会出现在房间快照或公开回放 API 中。
- 如果某项操作不可用，请依次检查连接状态、玩家身份、已选套牌和准备状态、区域拥有权/操控权、游戏是否已经结束，以及当前是否打开了模态弹窗。

## 17. 反馈与报告

官方 3.1.0 的反馈是**公开提交**。你批准的文字、技术信息、附件和后续回复会发布到 GitHub 的 `ClayStan404/hexproof` 仓库，任何人都可以查看和复制。没有私密提交或联系邮箱输入框。请勿包含密码、令牌、联系方式、私人对话、非公开对局信息或他人的个人信息，图片中也不能包含这些内容。

可从主菜单、页面导航或牌桌操作菜单打开**反馈**。反馈不依赖游戏服务器连接或账号登录，自定义游戏服务器也不会成为反馈接收方。表单打开时会阻止牌桌输入，但对局和计时仍会继续。离线时可以保存和导出草稿；构建未启用、配置错误和暂时连接失败会分别提示。

### 预览并公开发布

1. 选择**问题**、**建议**或**其他**，说明操作步骤、预期结果和实际结果。描述最多为 8 KiB 的 UTF-8 文字。
2. 可添加最多两张静态 PNG/JPEG 图片、一份 Forge 崩溃报告和一份托管诊断。通过**预览**、**移除**和**技术信息**检查选中的内容。客户端不会自动截取桌面；只有主动选择**粘贴图片**才会读取剪贴板图片。
3. 等待**草稿已保存**，点击**预览公开反馈**，逐项检查文字、技术信息、附件和公开仓库。**阅读完整说明**会在客户端内显示完整告知，包括 AI 服务商和保留、移除规则。
4. 勾选**我已查看这些内容及说明，并同意公开发布。**，再点击**公开发布反馈**。仅查看预览、阅读说明或勾选复选框都不会上传；修改草稿后必须重新预览和确认。

3.1.0 要求图片原文件和规范化后的 PNG 都不超过 2 MiB，单边不超过 8192 像素，总计不超过 1600 万像素。移除图片元数据不能遮住画面里的隐私。大截图被拒绝时，可先缩小或裁剪一份副本，再检查并添加。
**未发布的源码改动：**后续源码可接收不超过 32 MiB、仍符合相同像素限制的 PNG/JPEG，必要时按比例缩小到不变的 2 MiB 上传上限。已发布的 3.1.0 安装包不含这项修复；原图片文件不会被修改。

### 停止、关闭和申请移除

- **停止发送**停止之后的客户端上传，但不能撤回已经发出的请求或已接收内容。
- **关闭反馈**停止请求后续处理和新回复，保留公开讨论及附件。已经运行的任务和公开 Issue 的关闭可能仍在同步，待处理或延迟状态会如实显示。关闭不是删除，原反馈也不能原地重新打开。
- **申请移除内容**单独请求从项目控制的位置移除整个反馈。误发敏感内容时应使用此操作，并联系完整说明中的支持地址；保留记录以查询进度。目前 Multica 的任务历史可能阻止清理完成，申请可能持续待处理；服务商记录、GitHub 历史、通知、备份及他人副本仍可能存在。
- **从本机删除**只删除这台设备的记录及其访问权限，不会删除服务已接收或公开的内容；有需要时应先申请远端移除。

草稿在本机保留到自行删除。已接收内容通常在本机保留最多 30 天，受存储限制影响；公开回执按界面所示访问期限保留，用于查状态和申请移除。官方接收服务默认保留公开内容和访问凭据 365 天，到期启动清理。移除未完成时仍保留其状态和授权；移除后状态记录再保留至少 120 天，以防重新发布。到期并不保证外部副本当天全部消失。

早期 V1 私密记录不会自动公开或交给公开 AI 流程，原有可信回执仍可查询。如要公开其中的可见内容，需要主动创建新的公开草稿并重新预览确认；旧联系邮箱和访问凭据不会复制过去。
