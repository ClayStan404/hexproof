# UI translations

Hexproof ships nine interface languages. English is the source language; the
other eight ship Qt translation catalogs embedded in the application:

| Code | Language | Main catalog | Dynamic catalog |
|------|----------|--------------|-----------------|
| `en` | English | *(source strings)* | *(source strings)* |
| `zh` | 简体中文 | `i18n/hexproof_zh_CN.ts` | `i18n/hexproof_dynamic_zh_CN.ts` |
| `ja` | 日本語 | `i18n/hexproof_ja.ts` | `i18n/hexproof_dynamic_ja.ts` |
| `fr` | Français | `i18n/hexproof_fr.ts` | `i18n/hexproof_dynamic_fr.ts` |
| `de` | Deutsch | `i18n/hexproof_de.ts` | `i18n/hexproof_dynamic_de.ts` |
| `es` | Español | `i18n/hexproof_es.ts` | `i18n/hexproof_dynamic_es.ts` |
| `it` | Italiano | `i18n/hexproof_it.ts` | `i18n/hexproof_dynamic_it.ts` |
| `pt_BR` | Português (Brasil) | `i18n/hexproof_pt_BR.ts` | `i18n/hexproof_dynamic_pt_BR.ts` |
| `zh_TW` | 繁體中文 | `i18n/hexproof_zh_TW.ts` | `i18n/hexproof_dynamic_zh_TW.ts` |

Interface language is independent from card language: card names, rules text,
and card art use the separate `cardLanguage` preference (currently English and
Simplified Chinese card data), and switching the interface language never
changes card data, match state, or hidden-information projections.

## Where the language registry lives

The mapping between the stored preference code, the language's own display
name, and the QM catalog base names is defined **once** in
`apps/client-qt/src/UiLanguages.h`. Everything else is driven from that table:

- `TranslationController` resolves which embedded QM files to install.
- `ClientPreferencesModel::setUiLanguage` and `DeckLibraryStorage` normalize
  and persist the stored code (`zh_cn` is accepted as a legacy alias for
  `zh`; unknown values fall back to `en`).
- `main.cpp` exposes the list to the Language settings screen as the
  `uiLanguages` context property; each option shows the language's own name.

Two places must stay in sync with that table because they cannot include C++:
the CMake locale lists (`HEXPROOF_UI_TS_LOCALES` and
`HEXPROOF_DYNAMIC_TS_LOCALES` in `apps/client-qt/CMakeLists.txt`) and
`LANGUAGES` in `tools/check-i18n.py`. Update all three lists together: the file
audit checks the catalogs registered in its own list, while the runtime tests
check that the compiled catalogs actually load. The file audit alone does not
compare the C++ and CMake registries.

## The two catalogs

**Main catalogs** are generated by lupdate over the application sources (QML
`qsTr`/`qsTranslate` plus C++ `tr()`):

```sh
cmake -S apps/client-qt -B build/client-qt -G Ninja
cmake --build build/client-qt --target update_translations
```

The build compiles every main catalog with lrelease and embeds the QM files
under `:/i18n` in the application, the native audit binary, and the QML test
binary (one shared resource list).

**Dynamic catalogs** are hand-maintained. They translate runtime status and
log strings that C++ builds (match logs, caching status, failures) and that
QML displays through `I18n.tr(...)`, which calls
`qsTranslate("HexproofDynamic", source)`. There is no source scanner for
these: the Simplified Chinese dynamic catalog is the authoritative template
list. When adding or changing a dynamic message, update every language's
dynamic catalog in the same change — `tools/check-i18n.py` verifies each
language covers the Simplified Chinese template.

## Updating or adding translations

1. After changing any `qsTr`/`qsTranslate` source string or C++ `tr()` text,
   rerun the `update_translations` target. lupdate marks removed strings
   `vanished` and new strings `unfinished` in every catalog.
2. Translate the `unfinished` entries in every language's catalogs. Preserve
   placeholders (`%1`…, `%n`, `%L1`…) exactly; plural messages
   (`numerus="yes"`) need the full form set for the language — one form for
   Japanese and Chinese, two for the Western languages. Vanished/obsolete
   entries never satisfy coverage and may be deleted when their source is
   permanently gone.
3. For dynamic messages, keep the source strings byte-identical to what the
   C++ layer emits, and mirror the change in all dynamic catalogs.
4. To add a new language: extend the table in `src/UiLanguages.h`, add the
   locale to both CMake lists and to `LANGUAGES` in `tools/check-i18n.py`,
   create empty `hexproof_<locale>.ts` and
   `hexproof_dynamic_<locale>.ts` catalogs (copy the dynamic template list
   from Simplified Chinese), run `update_translations`, and translate.

## Game terminology

Use Magic's localized vocabulary in actions, zone labels, prompts, and logs,
including both catalogs. Ordinary dictionary translations can describe a
different concept. Keep the complete surrounding sentence grammatical when a
term changes gender or case. Reference examples:

| Locale | Source concept | UI terminology |
|--------|----------------|----------------|
| `de` | Scry; token; counter on a card | Hellsicht; Spielstein; Marke |
| `fr` | Scry | Regard |
| `it` | Scry; in-game library | Profetizzare; grimorio |
| `pt_BR` | Scry | Vidência |
| `zh_TW` | Sorcery; graveyard; command zone; mana; draft | 巫術; 墳墓場; 統帥區; 魔法力; 輪抽 |

Consult Wizards' keyword glossaries in
[German](https://magic.wizards.com/de/keyword-glossary),
[French](https://magic.wizards.com/fr/keyword-glossary),
[Italian](https://magic.wizards.com/it/keyword-glossary), and
[Brazilian Portuguese](https://magic.wizards.com/pt-BR/keyword-glossary), plus
the Traditional Chinese [Commander guide](https://magic.wizards.com/zh-Hant/formats/commander)
and [Origins mechanics](https://magic.wizards.com/zh-Hant/news/feature/magic-origins-mechanics).
German battlefield UI uses *Spielfeld*, also used by the official
[Arena interface descriptions](https://magic.wizards.com/de/news/mtg-arena/renewal-mtg-arenas-2021-standard-rotation-2021-07-02).

A player-defined numeric tally is a generic counter control, distinct from a
rules counter on a permanent; do not replace every occurrence of "counter"
without checking its context. Likewise, the in-game library is distinct from
the application's saved deck library. Catalog corrections never translate
user-entered names, card data, protocol IDs, or engine responses.

## Checks and fallback rules

`tools/check-i18n.py --strict` runs in the shared static gate over all
languages and verifies: missing literal QML messages, unfinished/empty
translations, duplicate `(context, source)` entries, placeholder integrity,
plural form counts, dynamic-template coverage against the Simplified Chinese
list, and per-language statistics. See the module docstring for the exact
coverage boundary (notably: lupdate-scanned C++-only strings cannot be proven
"missing" by the QML literal scan, which is why the missing check is literal
based).

An entry marked `type="unfinished"` fails the strict audit even when it still
contains text or a complete set of plural forms. Such text can be a retained
draft after lupdate changes the English source; it must be reviewed before its
unfinished marker is removed. Advisory mode reports it without failing.

Fallback behavior at runtime:

- Connection send failures keep their original diagnostic text in the client
  state. Banners translate the `connection` error code at display time, so an
  existing error follows interface-language changes without rewriting it.
- A message missing from the installed catalog falls back to its English
  source text (Qt source-string fallback).
- An unknown or unsupported language code, or a catalog that fails to load,
  installs no translator and shows the English interface.
- Remote announcements and sponsor content are content data, not UI
  translations; the content service keeps its existing per-language data files
  and falls back to English when content for the selected language is absent.
- Unrecognized Forge effect text is shown as delivered by the engine;
  translation never alters option IDs, command values, response payloads, or
  server-authoritative state.
