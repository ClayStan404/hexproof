# Hexproof 3.4.0

## English

**Compatibility: coordinated upgrade required**

- This source uses game protocol `hexproof.v3` and internal cluster RPC
  `hexproof.cluster.v2`. Released 3.3.0 uses `hexproof.v2` and
  `hexproof.cluster.v1`; those peers cannot interoperate with this baseline.
  Admission requires exact game-protocol equality, independently of application
  version. Equal application versions cannot bypass a mismatch, and different
  versions with the same protocol are not rejected for their version numbers.
  There is no protocol negotiation or fallback.
- Clients and the hubs they connect to must transition together to v3. Official
  cluster routing additionally requires a coordinated cluster.v2 transition of
  the coordinator, hubs and paired home connectors. Old RPC peers are rejected;
  installing only a new client or only a new server does not bridge the change.
  Server-side pack-plan validation, private pack generation and creation/start
  replay protection require the updated hub; these are not client-only features.
  Finish occupied rooms before separately authorized service changes. Protocol
  compatibility does not provide live game migration or nondisruptive restarts.
- The player-host helper protocol remains 1 and Forge adapter revision remains
  34, but the full Forge runtime content identity changes from 3.3.0 for the
  target-rule fix below. Forge execution, player hosting and engine handover
  retain exact helper/runtime and artifact checks. Update the selected runtime
  when using that fix; ordinary players and spectators need no local Forge
  installation. This source preparation does not establish a live fleet
  transition, update readiness, release qualification or publication, and does
  not enable optional Forge services.

**Changes since 3.3.0**

- **Mixed online Set Sealed.** Customize one shared recipe totaling 1–12
  boosters per player, including combinations such as 2+2+2 across sets. The
  default remains six boosters of one set. Every player receives independent
  samples of the same locked recipe. Creation and registration show its
  composition; private pack groups preserve the actual product boundaries
  through reveal, reconnect, construction and the Swiss handoff. Non-six-pack
  recipes are custom and carry no sanctioned-format or balance guarantee.
- **Ordered online Set Draft.** Choose one installed preferred Limited product
  for each of exactly three rounds. A/B/A retains that order, including mixed
  pack sizes such as 14/15/14; all seats use the same product within each round.
  Pass direction remains left/right/left. Final cards still require selection
  and confirmation, including after reconnect. Stable creation/start operations
  and expected-stage checks prevent duplicate creation, pack rerolls and
  unintended stage advancement. Offline practice and Cube profiles are
  unchanged; this does not add offline mixed-product practice or saved recipe
  presets.
- **Estimated Star Trek Play boosters.** An updated card database can provide
  `hexproof-trk-play`, a maintained 14-card estimate using English TRK/SDS
  printings, for manual Set Sealed and Draft. Its approximate collation and
  disclosed probability assumptions are not factory-sheet accuracy, measured
  print-run rates or Arena equivalence. Collector-only, promo, Commander and
  Klingon-script printings are excluded; specialty products are not supported
  by this recipe. A usable upstream TRK Limited product supersedes the estimate.
  Card data is updated separately, existing events keep their locked product,
  and catalog availability does not establish Forge support for these cards.
- **Scoped Forge target rejection fix.** When native target selection rejects
  a card because of a cross-target restriction, the adapter keeps that refusal
  nonfatal and lets Forge refresh the prompt. The real-engine regression uses
  Agadeem's Awakening: a second target with the same mana value is refused,
  another legal target can be chosen, and the spell resolves. Genuine engine
  exceptions and refusals in other input families retain their error behavior.
  This does not establish that the broader reported crash is resolved.
- **Manual-table synchronization.** Snapshot updates reconcile the table once
  after typed card data and scalar state are committed. Reentrant snapshot,
  clear and sideboard updates are serialized so older state cannot overwrite a
  newer update. Forge lifecycle ownership is consolidated without changing
  gameplay rules. Release promotion also retains the merged fresh-TLS evidence
  gate; these notes do not attest that the gate has passed for 3.4.0.

**Packages and installation limits**

Client targets remain Windows 10/11 x64 (portable ZIP), macOS 13+ Apple
Silicon/ARM64 (zipped app), and Linux x86_64 (tarball, Ubuntu 24.04 runtime
baseline). Server packages target Linux AMD64 and ARM64. Linux clients depend
on compatible system C/C++ libraries and graphics/input support. Exit Hexproof
before manually replacing these portable archives; a verified updater download
does not apply itself. macOS packages may be ad-hoc signed or lack Apple
notarization. Follow the workflow-managed installation/signing notice on the
actual release, including any first-launch instructions.

**Validation limits**

Included changes have scoped Go, race, Qt, real-engine and Linux native evidence;
the mixed Sealed/Draft and TRK scenarios reached construction and match handoff.
Those scenarios do not establish complete Swiss-event coverage, Windows/macOS
native behavior, Qt 6.5 coverage or every Forge card interaction. The target-rule
regression passed in the real engine, but the separate live two-client target
scenario did not reach its target, and successful engine-to-Qt response coverage
and the original Windows/three-player Commander crash remain unverified. Public
issue #38 remains open pending the original card/ability and click sequence.
Complete verification of the final frozen 3.4.0 source, first-v3 artifact and
legacy-rejection qualification, supported-platform packages, fleet/update
readiness and final publication assessment remain separate release steps; the
existing development evidence and these notes do not attest their completion.

## 中文

**兼容性：需要协调升级**

- 本源码使用游戏协议 `hexproof.v3` 与集群内部 RPC `hexproof.cluster.v2`。已发布的 3.3.0 使用 `hexproof.v2` 与 `hexproof.cluster.v1`，这些旧组件无法与本基线互通。连接准入要求游戏协议完全相同，与应用版本号独立：版本号相同不能绕过协议不匹配，同协议的不同应用版本也不会仅因版本号而被拒绝。没有协议协商或回退。
- 客户端及其连接的游戏服务器必须协调切换至 v3；官方集群路由还要求协调器、游戏服务器及配对的 home connector 协调切换至 cluster.v2。旧 RPC 组件会被拒绝，仅更新客户端或仅更新服务器均无法跨越此边界。服务端补充包计划验证、私有补充包生成及创建／开始操作防重放需要新版游戏服务器，并非纯客户端功能。服务变更须另获授权并先结束占用中的房间；协议兼容不提供实时对局迁移或无中断重启。
- 玩家托管辅助组件协议仍为 1，Forge adapter 修订仍为 34，但为包含下述目标规则修复，完整 Forge 运行时内容身份较 3.3.0 已变化。引擎执行、玩家托管及引擎接管仍须通过精确辅助组件／运行时身份与产物校验。使用该修复时须更新所选运行时；普通玩家和观战者无需本地安装 Forge。本次源码准备不代表线上集群已切换、更新已就绪、发布资格已通过或版本已发布，也不会启用可选 Forge 服务。

**自 3.3.0 起的变化**

- **在线混合系列现开。** 可定制所有玩家共用的配方，每人合计 1–12 包，例如跨系列的 2+2+2；默认仍为同系列六包。每位玩家独立抽取同一锁定配方，创建及报名阶段展示组成，私有补充包分组在开包展示、重连、构筑及瑞士轮交接中保留真实产品边界。非六包配方属于自定义玩法，不保证符合认证赛制或平衡性。
- **在线有序系列轮抽。** 恰好三轮，每轮可选择一个已安装的首选限制赛产品。A/B/A 保留该顺序，可混用 14/15/14 等不同包大小；同轮所有座位使用相同产品。传包方向仍为左／右／左，最后一张牌仍须选择并确认，重连后亦然。稳定的创建／开始操作及预期阶段校验防止重复创建、重抽补充包和意外推进阶段。离线练习与 Cube 配置保持原状，本次不增加离线混合产品练习或已保存配方预设。
- **估算的星际迷航 Play 补充包。** 更新后的卡牌数据库可提供 `hexproof-trk-play`，使用英文 TRK／SDS 印次组成维护中的 14 张估算配方，供手动系列现开和轮抽使用。其近似配包及公开的概率假设不等同于工厂配牌表、实测印刷概率或 Arena 配包。该配方排除聚珍专属、赠卡、指挥官及克林贡文字印次，不支持特殊产品；可用的上游 TRK 限制赛产品会取代此估算。卡牌数据须另行更新，已有赛事保留锁定产品，目录可用也不代表 Forge 已支持这些牌。
- **限定范围的 Forge 目标拒绝修复。** 原生目标选择因跨目标限制拒绝某张牌时，适配层不再将该拒绝当作致命错误，而让 Forge 刷新提示。真实引擎回归使用 Agadeem's Awakening：拒绝第二个法术力值相同的目标后，仍可选择另一个合法目标并完成结算。真实引擎异常及其他输入类型的拒绝仍保留原有错误处理；这不代表范围更广的崩溃报告已解决。
- **手动桌面同步。** 快照先提交类型化卡牌数据与标量状态，再统一协调一次桌面；重入的快照、清空及换备更新按序执行，避免旧状态覆盖新更新。Forge 生命周期职责集中管理，不改变游戏规则。发布提升仍保留已合入的新鲜 TLS 证据门禁，本说明不证明 3.4.0 已通过该门禁。

**安装包与安装限制**

客户端目标仍为 Windows 10／11 x64（便携 ZIP）、macOS 13 及以上 Apple Silicon／ARM64（压缩应用），以及 Linux x86_64（tarball，以 Ubuntu 24.04 为运行时基线）；服务器目标为 Linux AMD64 与 ARM64。Linux 客户端依赖兼容的系统 C／C++ 库及图形／输入支持。手动替换便携归档前须退出 Hexproof；更新器校验下载后不会自行应用。macOS 包可能仅为临时签名或未经 Apple 公证，须遵循实际发布中由工作流附加的安装／签名提示及首次启动说明。

**验证范围限制**

所含改动已有按范围执行的 Go、竞争检测、Qt、真实引擎及 Linux 原生证据；混合现开／轮抽和 TRK 场景已到达构筑及对局交接。这些场景不能证明完整瑞士轮赛事、Windows／macOS 原生行为、Qt 6.5 或所有 Forge 卡牌交互已验证。目标规则回归已在真实引擎通过，但另一次双客户端实机目标场景未到达目标步骤，成功的引擎至 Qt 响应链路及原始 Windows／三人指挥官崩溃仍未验证。公开 issue #38 仍待补充原始卡牌／异能及点击顺序。最终冻结的 3.4.0 源码完整验证、首个 v3 产物及旧协议拒绝资格验证、受支持平台安装包、集群／更新就绪和最终发布评估均属于独立发布步骤；已有开发证据与本说明不证明这些步骤已完成。
