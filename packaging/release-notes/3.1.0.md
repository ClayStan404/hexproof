# Hexproof 3.1.0

## English

- **Independent application and protocol versions.** Client and server application
  versions may differ when both use the same game protocol. Clear mismatch
  messages identify the required upgrade and stop reconnect loops. Official
  cluster routing and transfer tickets also respect protocol compatibility.
- **Smoother table and deck interactions.** Creature piles distinguish combat
  states. Compact phase controls retain the complete phase list and fit taller
  translated fallback fonts. Deck-editor
  cache progress, fast scrolling and previews have more stable behavior.
  Replacing a battlefield view clears obsolete combat grouping so matching
  creatures can regroup correctly.
- **Feedback ready for AI conversations.** The implementation supports specific
  questions, replies grouped by case, resumable reply drafts, concise progress
  and verified public release versions. Later replies retain earlier delivery
  history. Closing feedback and requesting content removal are separate actions.
  Legacy private records retain their original protections.
- **Native AI development integration.** The optional Multica/Mika connection
  and small JSON tools support public conversations and progress; the native
  platform coordinates development and review.

**Upgrade requirement:** 3.1.0 uses `hexproof.v2`; installed 3.0.0 clients and hubs
use legacy v1. The first transition requires coordinated client, hub, coordinator
and paired home-connector upgrades. Old and new protocols cannot communicate.
After this transition, matching application versions are no longer required when
the game protocol matches. Forge runtime/helper identity checks still apply.
Release assets include verified protocol metadata in `compatibility.json`.

**Availability:** Online public feedback remains disabled in the packaged defaults
until its receiver, disclosure and native connection are activated. Local drafts
remain available. Automatic source publication and scheduled AI releases are
prepared but inactive. Building these packages does not deploy game servers or
the feedback receiver. Linux x86_64, Windows x64, macOS ARM64 and Linux
AMD64/ARM64 server packages are built by the public release workflow; macOS
installation/signing notes supplied by that workflow also apply.

## 中文

- **应用版本与通信协议分离。** 客户端和服务器只要使用相同的游戏协议，就可以运行不同的应用版本。协议不匹配时会明确提示需要升级的一方，并停止反复重连。官方跨服分配和转服凭据也会检查协议兼容性。
- **桌面操作和套牌编辑更顺畅。** 生物堆叠会区分攻击、阻挡和未参战状态；切换战场视图后不再恢复过期战斗分组，相同生物可以正确重新合堆。紧凑阶段操作仍保留完整阶段列表，并适配中文等回退字体的高度；改善套牌编辑器缓存进度、快速滚动和卡牌预览的稳定性。
- **反馈支持与 AI 持续对话。** 已实现具体追问、按原始反馈归组的回复、继续编辑回复草稿、处理进度和经过核实的公开发布版本。用户补充新情况后仍保留历史处理记录。关闭反馈与申请移除内容分别操作，旧版私密反馈继续受到原有保护。
- **接入原生 AI 开发流程。** 可选的 Multica/Mika 连接和轻量 JSON 工具支持反馈对话和进度回传，由平台协调开发与审核。

**升级要求：** 3.1.0 使用 `hexproof.v2`，已安装的 3.0.0 客户端和服务器使用旧版 v1。首次迁移需要配套升级客户端、游戏服务器、集群协调端及家庭节点连接器，新旧协议无法互通。完成首次迁移后，只要游戏协议一致，就不再要求应用版本完全相同。Forge 运行时和辅助组件仍保留各自的兼容性检查。发布包包含 `compatibility.json` 协议元数据。

**功能开放状态：** 安装包默认仍关闭在线公开反馈，待接收服务、公开说明和原生连接启用后开放；本地草稿仍可使用。自动源码同步和 AI 定时发布已准备，但尚未启用。构建安装包不会自动部署游戏服务器或反馈服务。公开发布工作流构建 Linux x86_64、Windows x64、macOS ARM64 客户端及 Linux AMD64/ARM64 服务端；macOS 的安装与签名提示以工作流附加说明为准。
